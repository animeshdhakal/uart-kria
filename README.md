# UART on AMD Xilinx Kria K26 SOM (KV260 / KR260)

This is a synthesizable SystemVerilog implementation of the UART protocol (8N1) targeted for the **AMD Xilinx Kria K26 SOM** (KV260 Vision AI Starter Kit / KR260 Robotics Starter Kit). It includes both RX and TX modules, a top-level character streamer, and a complete hardware wrapper configured with the Zynq UltraScale+ MPSoC Processing System (PS).

All simulation testbenches use cocotb and Verilator. The Vivado implementation flow follows a clean TCL-first approach driven via CLI.

---

## Architecture

On the Kria K26 SOM (KV260 / KR260), there is no dedicated external PL oscillator connected directly to fabric pins. Instead, the PL clock (`pl_clk0` at 100 MHz) and active-low reset (`pl_resetn0`) are generated by the Zynq UltraScale+ MPSoC Processing System (PS) block.

- `rtl/uart_tx.sv` — Transmitter module (8N1 framing, configurable baud rate).
- `rtl/uart_rx.sv` — Receiver module with 2-stage input synchronizer.
- `rtl/top.sv` — Pure RTL UART module that repeatedly transmits `"Animesh"` every 1 second over UART TX. Tested directly in cocotb.
- `rtl/kria_top.sv` — Hardware top-level for Kria K26 SOM. Connects the Zynq MPSoC PS clock (`pl_clk0` = 100 MHz) and reset (`pl_resetn0`) to `top.sv`, routing `uart_tx` to PMOD Pin 1.
- `scripts/create_bd.tcl` — Generates the Vivado Block Design (`system.bd`) with the `zynq_ultra_ps_e` IP configured with official Kria board presets.

## Hardware Pinout & Wiring

The UART TX signal is mapped to package pin `H12` (Bank 45, 3.3V LVCMOS) in [constraints/pins.xdc](file:///Users/animesh/Developer/uart/constraints/pins.xdc):

- **KV260**: PMOD Connector **J2 Pin 1**
- **KR260**: PMOD Connector **3 Pin 1**

### Connecting to a USB-to-UART Adapter (e.g., CP2102, FT232, CH340)

| KV260 PMOD J2 Pin | FPGA Pin | Signal / Function | Connect to USB-UART Adapter |
| :---: | :---: | :---: | :---: |
| **Pin 1** (Top-Left) | `H12` | `uart_tx` (FPGA TX output) | **RXD** (Adapter RX input) |
| **Pin 9** or **10** | GND | Ground | **GND** |

> [!NOTE]
> Serial terminal settings: **115200 baud, 8 data bits, no parity, 1 stop bit (8N1)**.

## Simulation (cocotb + Verilator)

Run the testbenches directly from the repo root:

```sh
uv run python sim/test_uart_tx.py
uv run python sim/test_uart_rx.py
uv run python sim/test_top.py
```

Build artifacts and waveforms (`.vcd`) are generated in `sim_build/<module>/`.

## Hardware Build (Vivado CLI)

The project and bitstream creation is fully automated via TCL:

```sh
# 1. Create the Vivado project and block design
make project

# 2. Run synthesis, implementation, write bitstream and generate .bit.bin
make build
```

This generates:
- `build/vivado/uart.runs/impl_1/kria_top.bit` — Standard FPGA bitstream for Vivado Hardware Manager / JTAG.
- `build/vivado/uart.runs/impl_1/kria_top.bit.bin` — Binary bitstream ready for Kria Linux (`fpgautil` / `xmutil`).

## Loading Bitstream onto Hardware

### Option A: Via Vivado Hardware Manager (JTAG)
1. Connect the micro-USB cable from your host to the KV260/KR260 JTAG/UART port.
2. In Vivado Hardware Manager, connect to target and program the device with `kria_top.bit`.

### Option B: On running Kria Linux (Ubuntu / PetaLinux)
1. Copy `kria_top.bit.bin` to the target board:
   ```sh
   scp build/vivado/uart.runs/impl_1/kria_top.bit.bin root@<kria-ip>:/tmp/
   ```
2. On the Kria board, load the bitstream into the PL:
   ```sh
   fpgautil -b /tmp/kria_top.bit.bin
   ```
3. Open a serial terminal on your host connected to the PMOD USB-UART adapter:
   ```sh
   picocom -b 115200 /dev/ttyUSB0
   ```
   You will see `Animesh` printed once every second.
